# AGENTS.md

## Setup
- Node >= 22.18 (`engines`; the web unit tests use Node's type stripping), pnpm 11, Rust stable >= 1.88 (`rust-toolchain.toml` adds rustfmt + clippy). `ffmpeg`, `ffprobe`, `yt-dlp` on `PATH` are optional: without them transcodes/durations answer 503 and YouTube/Instagram/X links aren't downloaded.
- `cp .env.example .env` — every setting of both processes is documented there. The API loads the repo-root `.env` itself; the web scripts use `node --env-file-if-exists ../../.env`; real environment variables win.
- `storage/` (SQLite DB, `covers/`, `songs/`, `transcodes/`) is gitignored and persistent. Never test against it: use a scratch `STORAGE_DIR` or a copy.

## Commands (run from repo root)
- Dev: `pnpm dev:api` (API debug build on `:3000`) and `pnpm dev` (web on `:4321`) in two terminals. `pnpm start:api` = `cargo run --release`; `pnpm build` + `pnpm start:web` = the built web app (`apps/web/server.mjs`).
- Checks: `pnpm lint` (`biome check .`), `pnpm format`, `pnpm typecheck` (`astro check` + `tsc` for `packages/types`), `pnpm test` (`cargo test`, then `pnpm -r test` = web unit tests `node --test 'src/**/*.test.ts'`; alone: `pnpm --filter web test`).
- Rust, in `apps/api-rs`: `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test`. Network tests are `#[ignore]`d: `cargo test --test covers_live -- --ignored`, `cargo test --test downloader_live -- --ignored`, `IMPORT_SHEET=<saved sheet.html> cargo test --lib live_sheet_snapshot -- --ignored --nocapture`.
- `pnpm test:contract` = `node --test 'apps/api-rs/tests/*.test.mjs'` against a running API (`API_BASE_URL`, default `http://127.0.0.1:3000`). `pnpm test:contract:local` (`scripts/contract-local.sh`, what CI runs) starts a throwaway API (fresh temp storage, fixture sheet, downloads and periodic syncs off) on a free port, waits for the import and runs the suite; `--build` and/or `--release` (re)build first or use the release binary; env `API_BIN`, `CONTRACT_PORT`, `CONTRACT_TIMEOUT` (s, default 60), `MEDIA_TOOLS`. On the fixture the cover and media success tests skip (no covers, no audio).
- CI (`.github/workflows/ci.yml`, push/PR to `main`): job `web` (install, lint, typecheck, `pnpm --filter web test`, build), job `rust` (`cargo fmt --check`, `cargo clippy --locked --all-targets -- -D warnings`, `cargo test --locked`), job `contract` (debug build, `pnpm test:contract:local`). `.github/workflows/ios.yml` (GitHub only, macOS): `YeTrackerKit` tests + unsigned IPA on changes to `apps/ios`; a tag `ios-v<version>` also makes a GitHub release and deploys the SideStore source (`scripts/sidestore-source.mjs`) to GitHub Pages. GitHub (`hkubus/yetracker-viewer`) is a Forgejo push mirror (`git push --mirror`): never create branches or tags on GitHub, they get deleted — tag on the origin.
- The API creates and migrates its DB on boot (inline DDL, additive `ALTER TABLE`s and backfills, the v1→v2 upgrade; all in `src/db.rs`). Reset: stop it and delete `storage/db.sqlite3*` (ids start over).

## Contract tests need a running server
`apps/api-rs/tests/{eras,songs,media}.test.mjs` (+ `helpers.mjs`) is a black-box suite; it discovers ids from `/eras` and plain `/songs`. `pnpm test:contract:local` does this for you on the fixture sheet (4 eras, 30 songs). By hand, e.g. against a copy of real data:

```sh
cargo build --release --manifest-path apps/api-rs/Cargo.toml
cp -r storage /tmp/yt-test
STORAGE_DIR=/tmp/yt-test SONGS_DIR=/tmp/yt-test/songs API_PORT=3100 \
  SYNC_ON_START=false SYNC_INTERVAL_MINUTES=0 DOWNLOADS_ENABLED=false \
  ./apps/api-rs/target/release/yetracker-api &
until curl -sf http://127.0.0.1:3100/health >/dev/null; do sleep 0.5; done
API_BASE_URL=http://127.0.0.1:3100 pnpm test:contract
```

- Always set `SONGS_DIR` too: the binary loads the repo-root `.env`, which may point it at real media. `SYNC_INTERVAL_MINUTES=0` + `DOWNLOADS_ENABLED=false` keep the run offline and repeatable.
- With `SYNC_ON_START=true` the import runs in the background after the listener binds: wait until `/status` reports `"lastImportOk":true` before testing.
- The fixture has no audio or covers, so the media success tests skip there; a copy of real storage exercises them. `MEDIA_TOOLS=present|absent` makes the transcode/duration expectations strict. Requests never delete media, but they fill the transcode cache and queue re-verification — keep the suite away from production data.

## Layout and entrypoints
- `apps/api-rs` — Rust/axum API (crate `yetracker-api`). `src/main.rs` boot (`.env`, logging, open-file limit, config, DB, temp-file cleanup, tool detection, bind, sync, serve); `src/http.rs` middleware stack (weak JSON ETags/304) + hyper server loop (timeouts, 60 s not-reading limit, connection limit with idle-then-stalled eviction, graceful shutdown); `src/sync.rs` the background sync driver; `src/routes/` (`mod.rs` route table, `EraId`/`SongId` extractors, `Params`, JSON helpers; `eras.rs`; `songs.rs` lists/search/detail, `downloadState`, search slots; `status.rs` `/health` + `/status`; `media.rs` stream/download/duration/cover + transcode cache). Helpers: `request.rs` (`Query`: one parameter rule for every route — last occurrence wins, trimmed, blank = absent), `error.rs` (`ApiError`), `rank.rs` (search ranking), `search_text.rs` (`fold`, search texts, sort keys, categories), `playable.rs`, `serve.rs` (validators, ranges, file bodies), `config.rs` (every env var). Jobs: `importer.rs` (parse, guards, stable ids, tombstones), `db.rs` (pool, DDL, migrations, `meta`), `downloader.rs` (songs + covers, backoff), `backfill.rs` (durations, re-verification, cleanup), `media.rs` (tools, ffprobe verdicts, quarantine, yt-dlp process groups), `public_net.rs` (SSRF guard). `tests/fixtures/sheet.html` is a trimmed real sheet. `apps/api-rs/HANDOFF.md` has the module map and schema notes; it and `RUST_PORT_PLAN.md` are otherwise history.
- `apps/web` — Astro 7 SSR (`@astrojs/node` standalone). `server.mjs` is the production entry (compression, asset caching, graceful shutdown); `env.mjs` next to it validates the runtime env for it, for `src/config.ts` (server-only: SSR `fetchApi`/`fetchJson` over `API_INTERNAL_URL`, `requestOrigin`, HTTPS detection) and for `astro.config.mjs` (dev listen address). A deployment is `dist/` + `server.mjs` + `env.mjs` (no `src/`, no `node_modules`: the build bundles everything), so `server.mjs` and `env.mjs` may only import `node:*` modules, each other and `dist/`. `src/middleware.ts` sets CSP, security and cache headers. Client code lives in `src/scripts/` (`player/**`, `song-list.ts`, `global-search.ts`, `home.ts`, `skip-link.ts`), pure helpers + their `*.test.ts` in `src/utils/`. See `apps/web/README.md`.
- `apps/ios` — SwiftUI app (Xcode 26.1+, iOS 26.1+, Liquid Glass; light and dark). All logic lives in the `YeTrackerKit` Swift package (Foundation + Observation, builds and tests on Linux); the app target only holds views and AVFoundation/MediaPlayer glue. `swift test --package-path apps/ios/YeTrackerKit` (Swift 6.1 on Linux: add `-Xlinker --allow-shlib-undefined`); `YT_LIVE_API_URL=http://127.0.0.1:3000` adds the live API smoke tests. In CI: `.github/workflows/ios.yml`. See `apps/ios/README.md` and `IOS_APP_PLAN.md`.
- `packages/types` — type-only contract v2 (`exports.import: null`), consumed via `workspace:*`; `test/contract.ts` type-checks example payloads.

## Quirks
- `API.md` documents contract v2 — trust `apps/api-rs/tests/*.test.mjs` as the source of truth. Route errors are `text/plain` + `Cache-Control: no-store` (e.g. `400 Invalid era id`); unknown routes `404 {"error":"Not found"}`; wrong methods `405 {"error":"Method not allowed"}` + `Allow`. Query parameters follow one rule on every route, media included: last occurrence wins, values are trimmed, blank = absent (`era=%20` is no filter); a route only validates the parameters it reads (`/eras/:id/songs` ignores `era=%FF`); ids, id filters and the media `quality` allow no leading zeros (`quality=064` is a 400).
- API is GET-only, public and read-only. Do not add private/admin routes without an auth layer. Every route reads `catalog_id = 'unreleased'` (`src/catalogs.rs`).
- `fold()` exists twice — `apps/api-rs/src/search_text.rs` and `apps/web/src/utils/search.ts` — and must produce identical output (the Rust tests mirror the TS vectors). Change both together. The same goes for category markers in a query (⭐ ✨ 🏆 🏅 🗑️ 🤖 anywhere, VS15/VS16 ignored: `SearchInput` in `routes/songs.rs` vs `categoryMarkersIn()` in `apps/web/src/songCategories.ts`) and for what an era-scoped search matches (the song's own text, not the era name/subtitle: `songs.song_search_text` vs the instant filter in `src/scripts/song-list.ts`).
- Player DOM contract (`apps/web/src/scripts/player/targets.ts`): lists never call the player. Play buttons are `button[data-play-target]` with `data-id`, `data-title`, `data-era-id`, `data-era-name`, `data-era-position`, `data-track-length` (the probed duration, else the sheet's length, in whole seconds cut off like the displayed length; empty when unknown), `data-dominant-color`, `data-has-cover`, `data-cover-version` and `aria-pressed="false"`; rows `[data-play-row]` (`hidden` rows are skipped); the queue scope is `[data-play-scope]`, optionally with `data-queue-era-id/-offset/-total/-params` (ignored while any row of the scope is `hidden`: a client-filtered list has no continuation). The player marks the current row `data-playing="true"` + `aria-current`, toggles `aria-pressed` and dispatches `yt:player-state` on `document`.
- ClientRouter lifecycle: client modules run once per document. Per-page setup runs on `astro:page-load` (and the first load); everything a page registers is released on `astro:before-swap` through one `AbortController`. Only truly global things (the persisted player, back links, the skip link's capture-phase click handler) register once.
- CSP: `script-src 'self'` — no inline scripts or `on*=` attributes; import modules from `<script>` tags (Vite never inlines `.js`, see `astro.config.mjs`). `style-src` allows inline styles; `connect-src`/`img-src`/`media-src` are `'self'` + the API origin. Client code gets the API URL from `<meta name="yt-api-url">` (`src/utils/api-base-url.ts`), never from `config.ts`.
- Web unit tests run TS through Node's type stripping: modules they import need explicit `.ts` import extensions and erasable syntax only (no enums, namespaces, parameter properties).
- `/songs/:id/stream?quality=` also takes `format=aac` and `start=<seconds>`: the iOS app needs them (AVPlayer cannot play Ogg, and it seeks a live transcode by restarting it). Keep both when touching the transcoder.
- Biome 2.5: single quotes, 2-space indent, 120 width (Swift follows the same indent/width via `apps/ios/.swift-format`; Biome skips `*.xcassets`). `apps/web/biome.json` just extends the root; `apps/api-rs/tests/fixtures/biome.json` excludes the verbatim HTML fixture.
- pnpm: only `esbuild` may run install scripts; `sharp` is not installed (passthrough image service).
